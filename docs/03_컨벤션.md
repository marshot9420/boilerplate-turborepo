## 변수명

모든 변수명은 줄임말을 쓰지 말고, 변수명이 길어져도 좋으니 길게 씁니다.

## 컴포넌트

컴포넌트는 기본적으로 `export default`를 사용합니다.

```tsx
interface ComponentProps {
    propName: string;
}

export default function Component({ propName }: ComponentProps) {
    return (
        ...
    )
}
```

그리고 `index.ts`에서 다음과 같이 `export` 합니다.

```ts
export { default as Component } from "./component";
```

만약 `forwardRef`를 사용한다면 화살표 함수를 사용합니다.

```tsx
"use client";

import { forwardRef } from "react";

interface ComponentProps {
    propName: string;
}

const Component = forwardRef<HTMLElement, ComponentProps>(
    ({ propName, ...props }, ref) => {
        return (
            ...
        );
    },
);

Component.displayName = "Component";

export default Component;
```

`index.ts`에선 마찬가지로 다음과 같이 `export` 합니다.

```ts
export { default as Component } from "./component";
```

컴포넌트의 변수명은 파스칼 케이스를 사용합니다.

```tsx
export default function PascalCase() { ... }
```

## 서버 액션

서버 액션은 유스케이스 별로 앞에는 create, register, update, edit, delete, remove 등을 사용하고, 그 뒤에 도메인명, 마지막에는 Action을 붙입니다.

```txt
createDomainAction
registerDomainAction
updateDomainAction
editDomainAction
deleteDomainAction
removeDomainAction
```

다만 조회 관련 서버 액션 함수는 작성하지 않습니다. 이상적인 RSC 흐름에 맞춰, 조회 기능은 앱 라우터(`apps/*/src/app`)의 `page.tsx`에서 서비스를 직접 호출합니다.

## 서비스

서비스 또한 유스케이스 별로 앞에는 create, register, get, update, edit, delete, remove 등을 사용하고, 그 뒤엔 도메인명, 마지막에는 Service를 붙입니다.

```txt
createDomainService
registerDomainService
getDomainByIdService
getAllDomainsAndCountService
updateDomainByIdService
editDomainByIdService
deleteDomainByIdService
removeDomainByIdService
```

다만 서비스에서 create를 사용했다면 서버 액션에서도 create를 사용해야 합니다. 나머지도 마찬가지 입니다.

## 기타

### 상수

상수는 대문자 스네이크 케이스를 사용합니다.

```ts
export const USER = {} as const;
```

```ts
export const PRODUCT_IMAGE = {} as const;
```

```ts
export const URLS = {} as const;
```

```ts
export const NAVIGATION_ITEMS = {} as const;
```

도메인 계층의 상수에는 각 필드 별로 해당 필드의 한글명과 제약 조건, 그리고 제약 조건에 대한 에러 메시지를 관리합니다.

```ts
export const DOMAIN = {
```


### Zod 스키마

Zod 스키마는 파스칼 케이스로 작명합니다.

```ts
import { z } from "zod";

import type { ListQuery } from "@repo/core/types";

import { USER } from "./user.constant";

export const UserIdParam = z.object({
  id: z.uuid(USER.ID.INVALID_MESSAGE),
});

export type UserIdParamInput = z.infer<typeof UserIdParam>;

export const UserListSortKeys = [
  "EMAIL",
  "NICKNAME",
  "ROLE",
  "STATUS",
  "CREATED_AT",
  "LAST_LOGIN_AT",
] as const;

export type UserListSortKey = (typeof UserListSortKeys)[number];

export const UserListQuerySchema = z.object({
  page: z.coerce.number().int().min(1).optional(),

  limit: z.coerce.number().int().min(1).max(100).optional(),

  keyword: z.string().trim().optional(),

  role: z.enum(UserRole).optional(),

  status: z.enum(UserStatus).optional(),

  sortKey: z.enum(UserListSortKeys).optional(),

  sortDirection: z.enum(["asc", "desc"]).optional(),
});

export type UserListQueryInput = z.infer<typeof UserListQuerySchema>;

export const UpdateUserProfileRequest = z.object({
  name: zNullableString().pipe(
    z.string().max(USER.NAME.MAX_LENGTH, USER.NAME.MAX_MESSAGE).nullable().optional(),
  ),

  avatarUrl: zNullableString().pipe(z.url(USER.AVATAR_URL.INVALID_MESSAGE).nullable().optional()),

  nickname: z
    .string()
    .trim()
    .min(USER.NICKNAME.MIN_LENGTH, USER.NICKNAME.MIN_MESSAGE)
    .max(USER.NICKNAME.MAX_LENGTH, USER.NICKNAME.MAX_MESSAGE)
    .regex(USER.NICKNAME.PATTERN, USER.NICKNAME.INVALID_MESSAGE),
});
```

각각의 유스케이스별 DTO 뿐만 아니라, IdParam, ListQuery와 같은 성격의 객체도 zod 스키마로 만들어서 한 곳에서 관리하고, 이를 서비스부터 UI 컴포넌트까지 공유해야 합니다. 즉, **요청 입력 타입**은 전부 Zod 스키마에서 한 번에 관리해야 합니다.

또한, normalizer가 필요한 경우 `"@repo/core/normalizer"`에서 한 번에 만들어 관리해야 합니다.

### DTO

DTO를 포함한 모든 타입들은 파스칼 케이스를 사용합니다. 이때, 응답 DTO는 뒤에 `Response`를 붙입니다.

```ts
interface UserResponse {}
```

```ts
interface UserDetailResponse {}
```

목록 조회 기능에 대한 응답 DTO의 경우, DTO를 정의할 때 목록 데이터를 염두에 두지 말고, 단일 데이터에 대한 DTO를 만듭니다. 그리고 사용 시에 다음과 같이 사용합니다.

```ts
export async function getUsersService(
  actor: UserPermissionActor,
  query: UserListQueryInput,
): Promise<Result<UserListResponse, AppError>> { ... }
```

## 바렐 패턴

`features`, `entities`, `views` 등은 각각의 도메인 별로 `export` 합니다.

```tsx
import { UserFeatureComponent, useUserFeatureHook } from "@/features/user";

import { UserEntityComponent, userEntityLibraryFunction } from "@/entities/user";

import { UserListView } from "@/views/user";
```

`shared`, `constants`, `hooks`, `types`, `config` 등은 해당 폴더 자체를 `export` 합니다.

```tsx
import { serverEnv } from "@/config";
import { URLS } from "@/constants";
import { useMediaQuery } from "@/hooks";
import { SomeType } from "@/types";
import { Shell } from "@/shared";
```

서버에서 사용되어야 하는 파일인 경우, export할 때 `server.ts`에서 상단에 `import "server-only";`를 표시하고 export 합니다.

```ts
export function createDomainService() {}
```

```ts
// server.ts
import "server-only";

export * from "./domain.service.ts";
```

"server-only"일 필요가 없을 경우, 나머지처럼 `index.ts`에서 export 합니다.

```ts
// index.ts
export * from "./domain.constant.ts";
```
