# 프로젝트 초기화

이 문서는 `boilerplate-turborepo`를 새로운 프로젝트의 시작점으로 사용할 때 필요한 초기 설정 절차를 설명합니다.

기본 흐름:

```txt
Boilerplate Clone
  ↓
Project Identity 초기화
  ↓
Dependency 설치
  ↓
환경변수 설정
  ↓
Database 준비
  ↓
Seed
  ↓
프로젝트 검증
  ↓
개발 서버 실행
```

프로젝트를 처음 만드는 과정에 집중하며, Database 운영 정책이나 Test 전략 등의 세부 내용은 각각의 전문 문서를 따릅니다.

---

## 1. 기본 초기화 순서

새로운 프로젝트에서는 다음 순서를 권장합니다.

```bash
git clone <boilerplate-repository-url> athena-doctrine
cd athena-doctrine

pnpm init-project athena-doctrine \
  --scope athena \
  --remove-git

pnpm install
```

환경변수를 설정한 뒤:

```bash
pnpm db:generate
pnpm db:push
pnpm db:seed

pnpm check
pnpm test

pnpm dev
```

즉 기본 순서는 다음과 같습니다.

```txt
Clone
  ↓
init-project
  ↓
pnpm install
  ↓
Environment
  ↓
Database
  ↓
Seed
  ↓
Validation
  ↓
Development
```

---

## 2. Boilerplate Clone

Clone할 때 실제 프로젝트 Directory 이름을 함께 지정하는 것을 권장합니다.

```bash
git clone <boilerplate-repository-url> athena-doctrine
cd athena-doctrine
```

`pnpm init-project`는 Repository Directory 자체를 Rename하지 않습니다.

역할을 다음과 같이 구분합니다.

```txt
git clone
  실제 Directory 이름 결정

pnpm init-project
  Repository 내부 Project Identity 변경
```

---

## 3. `pnpm init-project`

`pnpm init-project`는 Boilerplate를 실제 프로젝트로 전환하기 위한 최초 초기화 명령입니다.

기본 형식:

```bash
pnpm init-project <project-name> [options]
```

Project Name과 Workspace Package Scope가 같다면:

```bash
pnpm init-project mars
```

처럼 사용할 수 있습니다.

결과:

```txt
Project Name
  mars

Workspace Package Scope
  @mars
```

Project Name과 Package Scope가 다르다면 `--scope`를 지정합니다.

```bash
pnpm init-project athena-doctrine --scope athena
```

결과:

```txt
Project Name
  athena-doctrine

Workspace Package Scope
  @athena
```

`init-project`는 Dependency 설치 없이 실행할 수 있도록 Node에서 직접 실행되므로 `pnpm install`보다 먼저 실행합니다.

---

## 4. `init-project`의 변경 범위

`init-project`는 현재 Repository의 Project Identity를 감지하고 새로운 값으로 변경합니다.

주요 변경 대상:

```txt
Project Name
Workspace Package Scope
Project Name의 snake_case 표현
Session Cookie Name
```

Boilerplate 기본값에서:

```txt
boilerplate-turborepo
@repo
boilerplate_turborepo
boilerplate_session
```

다음 명령을 실행하면:

```bash
pnpm init-project athena-doctrine --scope athena
```

다음 형태로 변경됩니다.

```txt
athena-doctrine
@athena
athena_doctrine
athena_doctrine_session
```

현재 Project Name은 Root `package.json`에서, 현재 Package Scope는 `tooling/scripts/package.json`에서 자동 감지합니다.

일반적인 초기화에서는 기존 값을 직접 지정할 필요가 없습니다.

필요한 경우에만 다음 옵션을 사용할 수 있습니다.

```bash
pnpm init-project mars \
  --from-name boilerplate-turborepo \
  --from-scope repo \
  --scope mars
```

---

## 5. `init-project`가 함께 처리하는 작업

Project Identity 변경 외에도 다음 초기 작업을 수행합니다.

### Local Environment 파일

파일이 존재하지 않는 경우 Example을 기반으로 생성합니다.

```txt
.env.example
  → .env.local

.env.test.example
  → .env.test.local

.env.e2e.example
  → .env.e2e.local
```

이미 존재하는 Local Environment 파일은 덮어쓰지 않습니다.

### 기존 생성물 정리

초기화 전에 남아 있을 수 있는 생성물을 정리합니다.

대표적인 대상:

```txt
node_modules
.turbo
.next
dist
coverage
out
```

초기화 이후 새로운 Project Identity를 기준으로 다시 Dependency를 설치합니다.

### Lockfile

`pnpm-lock.yaml`은 문자열 치환 대상으로 직접 수정하지 않습니다.

Project Name과 Package Scope를 변경한 뒤:

```bash
pnpm install
```

을 실행하여 현재 Workspace 상태에 맞게 갱신합니다.

## 6. Dry Run과 Git History

실제 변경 전에 결과를 확인하려면 `--dry-run`을 사용합니다.

```bash
pnpm init-project athena-doctrine \
  --scope athena \
  --dry-run
```

`--dry-run`에서는 파일을 변경하지 않고 변경 예정 범위를 출력합니다.

새 프로젝트에서 Boilerplate의 기존 Git History를 제거하려면:

```bash
pnpm init-project athena-doctrine \
  --scope athena \
  --remove-git
```

을 사용합니다.

기존 History를 유지하려면:

```bash
pnpm init-project athena-doctrine \
  --scope athena \
  --keep-git
```

을 사용합니다.

`--remove-git`과 `--keep-git`은 동시에 사용할 수 없습니다.

기존 Git History를 제거했다면 초기화 이후 새로운 Repository를 시작할 수 있습니다.

```bash
git init
git add .
git commit -m "chore: 프로젝트 초기화"
```

Commit 규칙은 `18_컨벤션.md`를 따릅니다.

---

## 7. `init-project`가 하지 않는 작업

`init-project`는 Project Identity와 Local Bootstrap까지만 담당합니다.

다음 작업은 자동으로 수행하지 않습니다.

```txt
Dependency 설치

실제 Secret 입력

외부 Provider 연결

Prisma Client 생성

Database Schema 반영

Migration 실행

Seed

Test 실행

개발 서버 실행
```

초기화 Script와 실제 Infrastructure 설정을 분리하여 각 단계의 책임과 실패 원인을 명확하게 유지합니다.

## 8. Dependency와 Environment 설정

Project Identity 초기화가 끝나면 Dependency를 설치합니다.

```bash
pnpm install
```

이후 생성된 Local Environment 파일을 확인하고 실제 개발 환경에 필요한 값을 입력합니다.

```txt
.env.local

.env.test.local
.env.e2e.local
```

일반 개발 환경은 `.env.local`을 사용합니다.

Test 또는 E2E 환경이 필요한 경우 각각의 Local Environment 파일도 설정합니다.

환경변수의 분류, Server / Client Boundary, Secret 관리 기준은 `06_환경변수.md`를 따릅니다.

---

## 9. Database 초기화

개발 환경의 필수 Environment Variable을 설정한 뒤 Database를 준비합니다.

기본적인 최초 개발 환경에서는:

```bash
pnpm db:generate
pnpm db:push
pnpm db:seed
```

순서를 사용할 수 있습니다.

역할:

```txt
db:generate
  Prisma Client 생성

db:push
  현재 Prisma Schema를 개발 Database에 반영

db:seed
  초기 개발 데이터 삽입
```

Migration, Test Database, E2E Database 등의 상세한 사용 기준은 `07_데이터베이스.md`와 `12_테스트_전략.md`를 따릅니다.

## 10. 프로젝트 검증과 개발 시작

Database와 Seed까지 준비되었다면 기본 검증을 수행합니다.

```bash
pnpm check
pnpm test
```

Database 변경이나 실제 Persistence 검증이 필요한 경우:

```bash
pnpm test:integration
```

을 추가할 수 있습니다.

E2E나 Production Build가 필요한지는 현재 프로젝트와 변경 범위에 따라 판단합니다.

검증 기준은 `12_테스트_전략.md`와 `16_개발_워크플로우.md`를 따릅니다.

기본 준비가 끝나면 개발 서버를 실행합니다.

```bash
pnpm dev
```

## 11. `pnpm setup:scope`

`pnpm setup:scope`는 새로운 프로젝트를 초기화하는 명령이 아닙니다.

이미 존재하는 프로젝트에서 **Workspace Package Scope만 변경할 때** 사용합니다.

기본 형식:

```bash
pnpm setup:scope <scope-name>
```

예:

```bash
pnpm setup:scope athena
```

현재 Scope가:

```txt
@repo
```

라면:

```txt
@repo
  ↓
@athena
```

로 변경합니다.

현재 Scope는 `tooling/scripts/package.json`에서 자동 감지합니다.

필요한 경우 기존 Scope를 직접 지정할 수 있습니다.

```bash
pnpm setup:scope athena --from repo
```

실제 변경 전 확인:

```bash
pnpm setup:scope athena --dry-run
```

Scope 변경 후에는 Workspace 상태를 다시 동기화하고 검증합니다.

```bash
pnpm install
pnpm format
pnpm check
```

필요하면 관련 Test도 실행합니다.

---

## 12. `init-project`와 `setup:scope`의 차이

두 명령은 목적이 다릅니다.

```txt
pnpm init-project

  새로운 Boilerplate Instance 초기화

  Project Name 변경
  Package Scope 변경
  Project Prefix 변경
  Session Cookie 변경
  Local Environment 파일 생성
  기존 생성물 정리
  Git History 처리
```

```txt
pnpm setup:scope

  기존 프로젝트의 Package Scope만 변경

  @old
    ↓
  @new
```

새로운 프로젝트를 시작한다면:

```bash
pnpm init-project <project-name>
```

를 사용합니다.

이미 개발 중인 프로젝트에서 Scope만 변경한다면:

```bash
pnpm setup:scope <scope-name>
```

를 사용합니다.

## 13. 초기화 완료 기준

다음 상태가 되면 기본 프로젝트 초기화가 완료된 것으로 봅니다.

```txt
Repository Directory가 실제 Project Name을 사용한다.

Root package.json이 실제 Project Name을 사용한다.

Workspace Package가 실제 Package Scope를 사용한다.

Dependency 설치가 완료되었다.

필수 Local Environment가 설정되었다.

Prisma Client가 생성되었다.

개발 Database Schema가 준비되었다.

Seed가 정상적으로 실행되었다.

pnpm check가 통과한다.

필요한 Test가 통과한다.

pnpm dev로 Application을 실행할 수 있다.
```

## 15. 빠른 시작

Project Name과 Package Scope가 다른 프로젝트를 새로 시작하는 전체 예:

```bash
git clone <boilerplate-repository-url> athena-doctrine
cd athena-doctrine

pnpm init-project athena-doctrine \
  --scope athena \
  --dry-run

pnpm init-project athena-doctrine \
  --scope athena \
  --remove-git

pnpm install
```

`.env.local`에 필요한 값을 설정한 뒤:

```bash
pnpm db:generate
pnpm db:push
pnpm db:seed

pnpm check
pnpm test

pnpm dev
```

핵심 순서만 기억하면 다음과 같습니다.

```txt
Clone
  ↓
init-project
  ↓
install
  ↓
env
  ↓
database
  ↓
seed
  ↓
check
  ↓
dev
```
